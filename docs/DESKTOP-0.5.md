# GRAFT 0.5.0 desktop distribution candidate

GRAFT is one cross-platform desktop application — Apple Silicon macOS and 64-bit Windows — packaging the existing local browser workspace and core inside Electron 44.3.0 using Electron Forge 7.11.2. One product, one $49 purchase, one Stripe product, one licensing backend, one licence key and one three-installation seat pool shared across both platforms; Mac users receive the macOS build and Windows users the Windows build. It does not host GRAFT execution remotely. The engine and CLI remain usable independently. Everything the application knows about the host OS lives in `packages/desktop/src/platform.js`; the rest of the code is shared.

## Building and installing

On an Apple Silicon development Mac, run `npm ci`, then `npm run desktop:make`. Forge creates `out/desktop/make/GRAFT-0.5.0-arm64.dmg` and a ZIP under `out/desktop/make/zip/darwin/arm64/`. The DMG is the installer/distribution artifact; copy GRAFT.app to Applications. The candidate has only a local ad-hoc development signature. It is **not notarized or suitable for public paid distribution yet**.

Verify a build with `npm run desktop:package -- --fixture` followed by `npm run desktop:accept`, which drives the packaged bundle end to end on whichever platform it runs. The customer does not need Node or npm for GRAFT itself. Git is a **product** requirement, not a development one: GRAFT's transplant lands on a recovery branch and writes receipts through the system git. On macOS that is the Command Line Tools shim (`/usr/bin/git`); on Windows it is Git for Windows on `PATH`. A clean-machine installation and prerequisite experience must be validated on each platform before accepting customers. Intel macOS and ARM Windows are not supported commercial targets.

## Windows

On a 64-bit Windows machine (or the `windows-desktop` CI job), `npm ci --ignore-scripts && node node_modules/electron/install.js`, then `npm run desktop:make`. Forge creates, under `out/desktop/make/squirrel.windows/x64/`, a **Squirrel.Windows one-click installer** `GRAFT-0.5.0-Setup.exe` plus the `RELEASES` manifest and `GRAFT-0.5.0-full.nupkg` it installs from, and a portable ZIP under `out/desktop/make/zip/win32/x64/`. Squirrel was chosen because it is the smallest Forge maker that yields an ordinary double-click `.exe` installer: it installs per user under `%LocalAppData%\GRAFT` with no administrator prompt, creates Start Menu and desktop shortcuts, and registers an uninstaller in *Settings → Apps*. No MSI is produced. `scripts/desktop/inspect-windows-artifact.mjs` validates the artifact (PE header, `RELEASES`↔`.nupkg` SHA1, bundled `node.exe`, ASAR exclusions, unset product configuration).

The Windows build bundles the official standalone Node 24.21.0 `win-x64` archive (SHA-256 `158f7685b44de51f6c0df1d153526cbcd3e1bc739a8dfc607721cef75de9e541`, verified by `scripts/desktop/prepare.mjs`) as `resources\runtime\node.exe`, and the same runtime containment, version and architecture checks apply. Verifier children are not detached into a process group on Windows (there are none); the existing `win32` branches in `packages/core/src/verify/http-runner.js` handle tear-down. The Windows executable carries the same GRAFT artwork as `packages/desktop/assets/icon.ico`, assembled from the committed master by `scripts/desktop/icon-ico.mjs`; regenerate it whenever the master changes.

A Squirrel install/update/uninstall launches the application once with a `--squirrel-*` argument; `packages/desktop/src/squirrel-startup.js` performs the shortcut housekeeping through `Update.exe` and exits (the standard `electron-squirrel-startup` behaviour, inlined so the client bundle carries no extra dependency). The native menu keeps About, License and Quit on both platforms and omits macOS-only roles on Windows. Closing the window quits the application on both.

**Unsigned release candidate — expected SmartScreen behaviour.** No Windows code-signing certificate has been purchased or configured, and `GRAFT_SIGN=1` is refused on Windows. `Get-AuthenticodeSignature` reports the installer as `NotSigned`; CI asserts exactly that. Consequently a downloaded `GRAFT-0.5.0-Setup.exe` shows Microsoft Defender SmartScreen's *"Windows protected your PC"* dialog with *Unknown publisher*; the tester must choose *More info → Run anyway* (a normal, informed decision for an unsigned beta), and browsers may also warn on download. This is the correct behaviour for an unsigned binary and GRAFT does nothing to suppress or bypass it. Before public paid distribution the installer must be signed (an EV or OV certificate with a timestamp; SmartScreen reputation then accrues), exactly as the macOS build must be notarized.

**State and reinstall semantics on Windows.** Application data lives under `%AppData%\GRAFT` (Electron `userData`), GRAFT state under `%UserProfile%\.graft`. Uninstalling through *Settings → Apps* removes the program under `%LocalAppData%\GRAFT` but, like most Windows software, leaves `%AppData%\GRAFT` in place — so a plain uninstall/reinstall keeps the encrypted installation identity and the activation, and re-activation reuses the same seat. Deleting `%AppData%\GRAFT\licensing` (or a fresh Windows user profile / a new machine) is a new installation that consumes a seat, identical to a wiped Application Support directory on macOS.

**What CI proves, what needs a desktop, what needs a clean PC.** The `windows-desktop` job runs the unit suites on Windows, packages the deterministic fixture and drives it end to end with the real Electron, real DPAPI-backed `safeStorage`, real git, and repositories under a directory containing spaces and non-ASCII characters (launch, sandboxed renderer and bridge, activation through renderer→preload→IPC, harvest→plan→apply→verify on the bundled Node, a native WM_CLOSE quit during live verification, clean shutdown, reopen, reopen offline within grace), then builds, validates and uploads the unsigned installer as the `graft-windows-x64-unsigned-release-candidate` artifact. What it cannot prove: SmartScreen and the first-run experience of the *installer itself* (a real interactive desktop session), and the prerequisite experience on a machine that has never had Git or a developer tool installed (a physical clean Windows PC). Those two remain manual gates before any Windows customer.

## Runtime and security

Every build downloads the official standalone Node 24.21.0 archive for the host platform (macOS ARM64 SHA-256 `bed7eea5325e1108f32ce5228ddd6a5f0f08a499ee42aa7442aea583702f6057`; Windows x64 above), verifies it, and extracts it afresh into application resources. Runtime resolution checks real paths and containment and probes the executable's version/architecture. Verification uses `Contents/Resources/runtime/bin/node`, preserves the `--` terminator, controlled environment, timeouts and POSIX process-group cleanup. It never falls back to PATH or Electron's executable; RunAsNode is disabled.

The renderer is sandboxed and context-isolated, with Node integration disabled. The preload exports only explicit licensing, version and folder-picker operations. IPC validates the sender and main frame. Remote navigation, redirects, popups, webviews and permissions are denied. External purchase/update links must be configured HTTPS URLs and open in the system browser. The local HTTP API retains its local execution defenses and also checks the main-process license gate.

The native menu provides About, License and Quit. Closing the window quits the app. Quit waits for the current operation and owned verifier children to finish. Abrupt OS termination/power loss still requires inspecting the existing recovery receipt; branch switching alone does not undo uncommitted files.

## Licensing and state

`packages/desktop/config/product.json` contains only non-secret expected store/product/variant IDs and purchase/download URLs. They are currently unset, so normal builds fail closed. Configure the GRAFT licensing backend values (`licenseApiBase`, `purchaseUrl`, `downloadUrl`, identity triple; see `packages/licensing/README.md`) before a paid build. No Stripe secret is embedded. The provider uses only the backend's activate/validate/deactivate API over HTTPS (the signing gate and the provider both refuse a non-HTTPS `licenseApiBase`; plain-HTTP loopback is tolerated only in unsigned test builds), with timeout and redirect refusal.

Activation checks license status, expiration, product/store/variant and activation instance. Each installation mints a random installation id once (no hardware fingerprinting) and persists it encrypted beside the activation record; it survives deactivation so re-activation from the same Mac is idempotent, while a reinstall (wiped application data) is a new installation that consumes a seat. The instance and key are encrypted through Electron safeStorage — the macOS Keychain or, on Windows, user-scoped DPAPI — in the application data directory, with mode-0700 directories and atomic mode-0600 files where POSIX modes exist (on Windows the per-user profile ACL provides the equivalent, and links are refused by inspection before the file is opened). The activation's descriptive name records the platform (`GRAFT desktop (macOS)` / `GRAFT desktop (Windows)`) for support; identity is always the installation id. A valid perpetual license has a 30-day offline grace measured from the last successful online validation. Network errors never create activation or extend that timestamp. Explicit invalid/expired/disabled responses revoke access. Clock rollback is refused. Failed deactivation retains the activation for retry. License operations do not modify project files.

Offline continuity depends on the existing local encrypted record. Deleting that record, losing the keychain or changing signing identity may require online activation. Local owners can alter their own program/state; this client license gate is not DRM or proof against a determined owner. Signed updates need consistent Developer ID identity and a real keychain upgrade test.

If deleting a revoked activation fails, GRAFT attempts to overwrite it with an encrypted revocation tombstone. Offline restart cannot revive that tombstone. If both deletion and writing fail, access is denied in the current process and a storage-repair message is shown. Durable revocation across restart cannot be guaranteed when the system permits no persistent changes; restore storage access and validate online before restarting.

Keychain operations have a 10-second deadline. A locked or unavailable keychain produces a storage error instead of indefinite activation. A late encryption response cannot persist an activation after the deadline. Keychain permission prompts must be completed locally by the user; GRAFT does not bypass them.

Projects, bank and receipts stay local. The desktop preserves `~/.graft` so existing state needs no automatic migration. Project receipts remain in each repository's `.graft`. Manual updates replace the app while retaining state. No auto-update server or telemetry is enabled.

## Signing and release blockers

Set `GRAFT_SIGN=1` only in the signing environment. Supply `APPLE_SIGN_IDENTITY`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID` externally; import the Developer ID certificate into that environment's keychain. Never commit credentials or certificates. Forge enables hardened runtime, entitlements and notarization. Fixture builds and missing product configuration are refused by the signing build gate. The production icon is `packages/desktop/assets/icon.png`, with the macOS `icon.icns` generated from it beside it; `GRAFT_ICON` may point at an alternative `.icns` for an experimental build only. Regenerate the `.icns` from the master with `sips` and `iconutil` whenever the master changes; the DMG volume icon uses the same file. macOS 26 draws every legacy `.icns` application icon on a system-generated tile in Finder, the Dock and Launchpad, exactly as it does for other apps that have not adopted Apple's Icon Composer format; the artwork itself is unchanged and earlier macOS versions draw it as-is. Adopting the Icon Composer format needs an Xcode asset-catalog step that Electron Forge does not provide, and belongs with the signed release work.

Before public distribution: supply real product IDs and safe purchase/download URLs, validate real activation/deactivation, provide Developer ID signing and notarization credentials, validate signatures and nested bundled Node entitlements, test on a clean Mac including Git prerequisites, and rerun the complete packaged workflow on the final artifact. Upload only that final signed/notarized installer to the external purchase/download platform.

The deterministic licensing fixture is a separate `GRAFT Fixture` app, built with `npm run desktop:package -- --fixture`. Its test provider is excluded from normal production ASAR archives. It requires an isolated `GRAFT_FIXTURE_HOME` and the key `GRAFT-FIXTURE-VALID`. Creating `offline` inside that isolated home simulates a network outage. Never distribute this test app as the paid product.

## Validation evidence

`npm run desktop:accept` runs the packaged gate against the real `GRAFT Fixture` bundle and disposable instrumented repositories; build it first with `npm run desktop:package -- --fixture`. On 2026-09-10 all 34 checks passed on macOS 26.6.2 (Apple Silicon).

The gate covers: the bundle launches and reports 0.5.0; verification uses the standalone Node inside application resources and never Electron; the renderer has no `require`, `process` or `Buffer` and only the explicit bridge; the window is sandboxed and context isolated; remote navigation is refused; the native menu offers About, License and Quit; the workspace API answers 402 before activation; activation succeeds through the real renderer, preload and IPC path; the renderer paints the workspace and lists both registered repositories; harvest verifies the source and banks the capability (VERIFIED 6/6); the preview includes the entrypoint edit; the transplant lands on a new recovery branch with a receipt and the destination verifies (VERIFIED 6/6); the instrumented projects really ran on the bundled Node with no surviving children.

It then issues a native macOS Quit while a verification is running. The application exits cleanly in well under a second, having waited for the verifier child that had already started, records a clean shutdown, leaves no verifier process behind, leaves the destination repository exactly as the transplant left it with no existing file rewritten or truncated, writes only a complete owner-only compatibility record from the finished run, and keeps the registry intact. Reopening afterwards restores the licence from the encrypted cache without re-entry and shows two projects, one banked organ, one transplant and one saved result on the recovery branch. Repeating the reopen with the licence service unreachable behaves the same, inside the bounded cached grace window, which the outage neither creates nor extends.

The final production DMG and ZIP each carry GRAFT.app 0.5.0. `codesign --verify --deep --strict` reports the bundle valid and satisfying its designated requirement, and the bundled Node binary verifies separately. The shipped ASAR contains the engine plus `acorn` only, with no test directories and no licensing fixture, and its product configuration is unset so the build fails closed. Launching that final bundle opens the licence page, refuses access with an explicit unconfigured-product message, exposes no Node primitives in the renderer, quits through the native Quit and leaves existing local GRAFT state untouched.

A rebuilt ad-hoc bundle has a new code identity, so macOS guards the previous `safeStorage` keychain entry. The application correctly fails closed with a storage error rather than waiting indefinitely, which is why the ten-second keychain deadline exists. Since Generalization Hardening 0.1 the *fixture* build no longer uses safeStorage at all: its non-secret licence lives in a build-stamped plain file under the fixture home (`fixture-activation.json`), a record from another fixture build is treated as absent, and no keychain entry is created; the packaged gate and the demo driver survive an ordinary fixture rebuild without any manual cleanup. Production builds are unchanged. A real distribution must keep one consistent Developer ID identity, and a keychain upgrade test remains required before shipping updates.

Production dependency audit reports zero advisories. Build-only tooling still has high-severity advisories in unpatched extraction and image dependencies; patched `tar` and `tmp` versions are pinned through overrides. Those packages are absent from the shipped application closure. Review that build-host exposure before public signing, and do not use a forced dependency downgrade as a substitute for validation.

No independent final review subagent was run for this candidate; the packaged evidence above is the basis for the release assessment.
