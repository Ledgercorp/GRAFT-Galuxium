Working behavior.
Inspectable evidence.

GRAFT is a local-first developer tool. Its local engine discovers capabilities, verifies source behavior, remembers revision-bound capability locally, classifies destination compatibility, creates a Blueprint, enforces external-data policy, applies an adaptation, and records typed destination evidence. The hosted page is a static evidence explorer for one real fixture run.

The demonstrated path

fixtures/old-saas-project provides email and password authentication with CommonJS, Node response handlers, and module state. fixtures/new-startup uses ES modules, return-response handlers, and a shared store. It has a conflicting placeholder login route; the local demo explicitly approves resolving that conflict.

GRAFT regenerates the supported capability in the destination idiom and wires it into the entrypoint. The displayed patch is the actual Git diff, including generated files. No AI service is used in this fixture workflow.

What VERIFIED means

Six required HTTP acceptance cases pass at source and destination. The seventh, optional session-after-restart case fails: the fixtures use in-memory sessions. Expand the cases in “Prove it” to inspect the recorded assertions. A successful required-case verdict does not prove durable sessions, production authentication security, or arbitrary architecture support.

Real evidence vs hosted replay

All revisions, Capability Memory identities, compatibility outcomes, refusal facts, custody events, Blueprint output, assertions, generated-file hashes, and patch contents come from local GRAFT runs against bundled fixtures. Buttons switch views of the same recorded data. There is no browser-side simulation of new execution, progress, or test results.

The disposable destination was committed after applying the transplant and then verified again, so the displayed destination revision identifies the tested code. Source and destination Git IDs belong to disposable fixture repositories, not commits in the GRAFT repository.

The public JSON is an allowlisted projection of local evidence. It contains no protected benchmark answer key, raw source prompt, credential, or private repository content. It includes proof-envelope digest identifiers, but omits the original envelopes and their private context. The projection has its own SHA-256 checksum, checked by the browser. Neither that checksum nor the displayed proof identifiers are signatures or independent attestations.

Your repositories stay local

The hosted directory contains only HTML, CSS, JavaScript, a brand image, and sanitized fixture evidence. It has no executor, upload endpoint, account system, analytics, licensing code, or mutable backend. The local GRAFT workspace is never hosted or tunneled.

Local verification runs project code with the user's OS permissions. GRAFT is not an untrusted-code sandbox; use trusted repositories. The sample authentication implementation is for demonstrating capability adaptation, not a production identity recommendation.

Reproduce the evidence

From the public source repository, use Node 20 or newer in a checkout and run node scripts/demo/judge-evidence.mjs. The producer uses the bundled fixtures, runs the real CLI demo, exercises the production compatibility and refusal paths, persists and reloads local Capability Memory, records Data Boundary decisions, exports a non-overwriting AGENTS.md handoff, performs revision-bound destination verification, validates its public projection, and writes packages/web/judge/evidence.json. It removes its disposable workspace after capture. Timestamps and fixture revisions change on regeneration.

The public schema rejects unknown fields and common sensitive patterns. HTTP bodies, cookies, environment values, raw reports, recovery receipts, local paths, operator data, and customer data are not exported. Automated filtering is complemented by review of the exact published directory.
